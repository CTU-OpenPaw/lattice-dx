# Authoritative local directory

`directory_people` is an administrator-synchronized Keycloak snapshot. API startup creates its schema before foundation and workflow storage. The API has no directory registration or write route. Workflow self-registration does not grant directory membership.

Bootstrap the local Compose stack with the current API, run `pnpm identity:sync-local` to install administrator-only organization attributes and the local fixture roles, then run `node scripts/sync-local-directory.mjs`. Repeat the directory sync after any user, role, department, organization, or enabled-status change. Existing fixture smoke scripts require this snapshot before assigning tasks.

The directory script reads actual Keycloak user UUIDs, enabled status, profile attributes, display names and effective realm roles through the administrator API in pages of 100. It does not change users, passwords, or roles. Local admin defaults match Compose; `LOCAL_KEYCLOAK_ADMIN` and `LOCAL_KEYCLOAK_ADMIN_PASSWORD` may override the login. It sends SQL through Docker Compose `exec -T postgres psql` stdin and logs only a count. The snapshot transaction disables all previous members then upserts current scoped identities; removed users, disabled users, and users without a valid organization remain unavailable. Failed collection leaves SQL untouched; failed SQL rolls back.

Organization attributes must have administrator-only edit permission in the Keycloak user profile. Department uses `department_id` only when its edit permission is administrator-only. Otherwise a single actual realm role among `department:warehouse`, `department:hr`, `department:it`, and `department:administration` supplies the department. Ambiguous or missing roles produce no department. Fixture identity/role provisioning is owned by `scripts/sync-local-realm.mjs` and `infra/config/keycloak/lattice-realm.json`; the directory does not use fixture usernames as subjects.

`GET /v1/directory/people` requires a verified RS256 bearer token with organization and `directory:read`. Filters: `role`, `department`, `q` (up to 200 characters), `limit` (1–100, default 50), `offset` (nonnegative safe integer). The server uses the token organization, active membership, literal case-insensitive display-name search, and display-name/subject ordering before pagination. It returns `items` with only `subject`, `organizationId`, `displayName`, optional `departmentId`, `roles`, and `page:{limit,offset,hasMore,nextOffset}`.

REST `/v1/tasks` and action `tasks.create` require the same verified active recipient in the creator's organization, including when no record is linked. The shared `requireAssignee` also supports a required recipient role for workflow consumers. Invalid or unavailable recipients return 400; a missing or failed directory returns 503. Authentication and authorization remain 401 and 403. The snapshot is not live Keycloak revocation: until the next successful sync, previous enabled status and roles remain authoritative. Offset navigation is not a stable snapshot across concurrent changes.
