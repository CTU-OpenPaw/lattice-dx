# Logistics UI backend handoff

Approved scope: implement the three groups proposed to Duy: shared directory/assignee validation/pagination, scoped work access, minimal Logistics order creation → warehouse assignment → receipt. Keep code focused; no UI, shipment, vehicle, finance, upstream changes, Notion ticks, automatic merge or release.

Build on PR #5 (still open). New branch starts at its head; final PR should target that branch until #5 merges, so reviewers see only this change.

Directory: administrator-synchronized `directory_people` registry has signed identity subject, organization, displayName, departmentId, enabled and roles. A local admin sync reads Keycloak users and realm roles; it does not accept browser-provided identity fields, writes no credentials, and disables removed/disabled members on synchronization. Snapshot freshness/disabled users are documented; sync is required after identity changes, not an assertion of real-time Keycloak validation. REST task creation and tasks.create use the same required active same-organization lookup, failing closed if missing/unavailable. Directory read needs `directory:read`, exposes only active members of actor's organization, supports role/department/search and pagination; self-registration does not grant directory membership.

Pagination shared contract: `limit` 1–100 (default 50), `offset` nonnegative safe integer, `q` ≤200 characters. `items` plus `page:{limit,offset,hasMore,nextOffset}`; stable sort includes UUID/subject tie-breaker. Filter by state/status/definition/record where applicable, apply visibility before pagination, fetch limit+1. Existing no-query calls still return items and default bounded first page. Offset is simple navigation, not a snapshot across concurrent writes.

Order is a `logistics_order` workflow run backed by records, same ID. API POST/GET `/v1/logistics/orders`, GET detail, POST `/:id/submit` and `/:id/receive`; both commands require expectedVersion and Idempotency-Key. Create body: title/customerName/deliveryAddress/sku/quantity (positive integer ≤1e6)/warehouseAssigneeId, optional clean attachmentId. Version 1 draft → submitted → received. Sales owns create/submit, only assigned warehouse actor with logistics:warehouse receives. Draft visible to owner only; submitted/received visible to owner or assigned warehouse actor with correct role, never all warehouse users in organization. Role/scope claims signed JWT only.

Engine gains trusted configuration for assigned-reader field/role/states, assignee-only transitions, optional input fields and positive integer input validation, and declared task assignment/completion hooks. Submit atomically creates one foundation task linked by recordId and `workflow_task_links`, audit and command result. Receive atomically completes linked task and advances run. Generic task decisions cannot independently complete workflow-linked tasks. Returned order contains taskId after submission. Task lists stay assignee-scoped; detail and file access for generic record-linked tasks grants only the assignee of a task issued by that record's owner in the same organization. Owner-only record linking stays unchanged, preventing fabricated tasks from sharing others' records. Workflow-linked files use workflow policy; unassigned roles cannot attach/use them.

Files attached at creation join workflow_files atomically; rejected/error/foreign/unreadable files fail before writes. Task-linked generic record files may be shared only when file owner is record owner. File content still requires files:read and clean scan. No broad directory, warehouse, record or file organization-wide read.

Acceptance: real JWT/API/SQL flow, REST/action unknown/foreign/disabled assignee denied without writes, eligible dropdown, pagination beyond 100 scoped records, sales create/submit and exact warehouse task/detail/files/receive, unrelated same-org warehouse and foreign-org denied, invalid quantity/recipient/file/version/key rejected, duplicate submit one task, concurrent receive one success, old workflows/action/bridge preserved. API handoff includes roles, errors, request/response and current snapshot limits.
