# System Studio: authoring to employee runtime

Approved scope from the conversation: compose a logical enterprise system from configuration, administer its lifecycle and use it as employees/managers. Reuse existing engine policy, workflow execution, modules, identity and UI host. Do not build a second workflow engine or change upstream software.

The implementation adds a small versioned authoring recipe (system title, modules/pages, typed input fields, requester/reviewer/handler roles and labels). Recipes are tenant-scoped durable drafts with optimistic revision and idempotent writes. A compiler generates existing enterprise module manifests and generic workflow/page configuration. The existing installer/publisher/enabler stays authoritative; installation remains disabled until every workflow is published and dependencies pass. These are explicit recoverable stages, not a claimed distributed atomic deployment.

The module manifest gains optional declarative presentation metadata: fixed renderer block names, labels, and references to its own workflow definitions. Existing manifests remain valid. Public runtime discovery returns only configured systems and role-visible definitions, not the full designer package or private dependencies. Existing backend authorization controls every operation.

An additive Studio route in the current NocoBase plugin uses the existing authenticated bridge. It provides a guided editor, draft list, preview/validation, staged publication, enable/disable, audit, package download/import and a runtime link. Runtime forms, workflow lists/inbox, transitions and history render from the published definition/labels; they do not add application-specific branches. A practical first template supports employee submission, manager approval/rejection and exact assigned employee completion, creating a real linked task.

Portable packages contain the recipe plus validated module manifest, no users, secrets or live business records. Recipe import can choose a new system ID/version and regenerate owned workflow IDs, permitting a second system in the same tenant. Keycloak remains the identity authority: Studio neither creates privileged accounts nor grants itself roles. Existing directory identities can be viewed/selected through authorized APIs.

Acceptance: a designer authors/publishes a new system from UI; alice submits; manager approves and assigns the configured employee; only that employee completes the linked task; history survives reload. A different employee/tenant is denied. Disable blocks new starts while existing runs remain readable/completable. Export/import creates a distinct reusable system without copying business records. SQL acceptance proves draft concurrency/replay/isolation and module/workflow lifecycle. Browser acceptance records exactly which actions actually ran. Do not tick Notion or rewrite README.
