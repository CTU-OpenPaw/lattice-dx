# Local database recovery rehearsal

Duy backend operations, no new dependencies. Local Docker core PostgreSQL only. Backup uses pg_dump custom format (consistent snapshot), stores artifact + SHA256 metadata under output/backups, excludes credentials from metadata. Restore rehearsal always generates dx_restore_[a-f0-9]{32} database; cannot target lattice/keycloak or arbitrary provided database. pg_restore uses --exit-on-error/no-owner/no-acl into new fixture; constraints/data restored, tables/count inventory collected. Drops only exact verified fixture database after all client processes close; never source database or volumes. Artifacts retained and git ignored because local business/file data can be present.

CLI node scripts/backup-core.mjs backup; node scripts/backup-core.mjs rehearse <absolute-or-relative-dump-path>. Rehearse verifies path inside output/backups, filename approved, manifest checksum/format, archive TOC; test captures sentinel record in source before dump and verifies sentinel in restored fixture using optional --record-id UUID. Binary output never routed through PowerShell text redirect or printed. Failure preserves backup; cleanup attempts fixture-only and propagates nonzero exit. Dump cap256MiB for local v1, not a remote backup/large enterprise storage service. No production data delete/restore-in-place mode.

Tests: path traversal/unsupported names/db source rejected, byte corruption checksum rejected, actual backup+restore through Docker with sentinel row and FK restoration success. Does not yet cover external object storage/Keycloak database/NocoBase or encrypted/offsite retention. Master phase8 must stay partial until readiness/retention/diagnostics are also done.
