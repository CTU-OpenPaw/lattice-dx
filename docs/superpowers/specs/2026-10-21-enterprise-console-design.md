# Enterprise console and configurable workflow Studio

User approved extending the product UI beyond a fixed request template. Keep the current engine, SSO, tenant boundaries, teammate branches and existing applications. Add four connected capabilities to the existing Foundation plugin; no upstream edits or new runtime dependencies.

1. **Console/navigation:** one enterprise home with published systems, personal inbox, capability-aware links, block/connector catalog and operations status. Studio, business workspace and administration share navigation and clear account context.
2. **Organization:** department creation/update including parent/manager and version checks; searchable paginated directory shows real roles and departments. Do not provision SSO identities or edit authority snapshots from the UI.
3. **Data:** schema editor with existing engine scalar types, revisioned save/publish; dynamic forms and paginated records, detail/update/history and person/department sharing. Employees can open an exact published schema/version without designer privileges; backend remains final authority.
4. **Composition/workflow:** optional page block selection plus ordered editable transitions, initial state, assigned visibility states, roles, task actions, input fields and equality conditions. Compile through existing workflow validator/module publisher; existing recipes retain identical manifests. Advanced connector/service execution is not fabricated: catalog displays registered IDs and availability; specialized workers remain separate integrations.

Use native accessible form controls and React/Ant Design already provided by NocoBase. Fixed bridge operations proxy exact existing API paths; never let a browser specify a URL, tenant or JWT. New writes use immutable command receipts/retries where supported; schema draft edits use existing revision checks (creation has no idempotency receipt, so uncertain creation is reconciled by ID before retry). Every paginated list offers navigation. Clear private state on session expiry and route/account change. Disabled capabilities show their actual availability.

Acceptance: a designer creates a department, authors/publishes a typed schema, creates and shares a record, composes a custom multi-step workflow with selected UI blocks, publishes a system, and employees/managers act through the same runtime. Console links make these paths discoverable. Signed HTTP/PostgreSQL tests prove role/tenant isolation and an extra review stage; browser verifies the main authoring/data/runtime paths.
