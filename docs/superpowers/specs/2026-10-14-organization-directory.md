Duy backend only, no deps/upstream/UI/adapter/Notion/credentials edits. Keycloak remains identity/token/roles authority. Engine directory is trusted admin-managed snapshot used for current resource membership; directory administration never creates Keycloak accounts or JWT roles. No hierarchy or manager implicitly grants entity/task/run access.

## Directory replacement

GET /v1/organization/directory-state directory:manage => {revision,updatedAt}. POST /v1/organization/directory-snapshot directory:manage strict {expectedRevision,people:[{subject,displayName,departmentId?:string,roles:string[],enabled:boolean}]}; mandatory key. Up to200 identities, roles0..50 distinct bounded100, total128KiB request; subjects unique, no organization/actor/credentials in items. Identity list sorted by subject and roles sorted for canonical snapshot. Explicitly privileged admin operation, not self-service profile editing; docs state it replaces one JWT organization snapshot, disables omitted members and doesn't alter JWT/Keycloak accounts. Disable/directory movement updates directory rows transactionally; shared-write FOR SHARE locks respected. Roles are directory metadata used for validated assignment, never caller JWT caps; service timer profiles require deployment allowlist, not just arbitrary snapshot roles.

Snapshot revision optimistic with org advisory lock; store revision/date, upsert supplied members, disable omitted identities in same tenant only, current authority before receipt. No deletion of people, source data/volumes. Snapshotaudit records actor/change count/revision/time only, not personal data payload; idempotent command receipt returns metadata revision, no raw roles. Local sync CLI stays supported but does not increment API snapshot revision; documented external sync must not race administrative replacement. Source lifecycle integration later chooses a single authoritative sync producer.
