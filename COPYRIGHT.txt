Pure-OSI Source Repository & External Host Runtime Boundary:
100% of the LatticeDX Git repository (https://github.com/CTU-OpenPaw/lattice-dx)
and the latticedx-1.0.0-src.tar.gz release archive consists strictly of
OSI-approved source code (Apache-2.0 first-party code + OSI-compatible npm
dependencies), with ZERO upstream/nocobase Git submodule and ZERO .gitmodules.
Host NocoBase runtime (nocobase/nocobase:2.2.50@sha256:04b75164936e7314ef74d82844bc56c9f34ed7ff1ca976ca53ffac2d3c88d777)
is loaded strictly at runtime as an external OCI container outside the Git
repository and is NOT modified, bundled into pnpm workspace builds, or
redistributed inside release tarballs. First-party plugins declare
"nocobase": { "sdkProvidedByHost": true }, invoke host SDK APIs at runtime,
and preserve NocoBase Clause 5.2 attribution ("Powered by NocoBase", "v2.2.50",
"https://www.nocobase.com", "License settings").

OSS License Purity Guarantee:
LatticeDX v1.0.0 strictly prohibits BSL-1.1 / Business Source License software
(including ThingsBoard and EMQX) across workspace code, lockfiles, and OCI
containers, enforced deterministically by scripts/generate-sbom.mjs and
scripts/verify-pof-readiness.mjs against docs/sbom-cyclonedx.json. Optional
external integration services such as n8n (n8nio/n8n:2.48.1) run strictly as
standalone external OCI containers and are never part of LatticeDX's core
automation engine.
